# Дизайн: офлайн-поставка модели BGE-m3 + сверка ревизии с Hugging Face Hub

Дата: 2026-11-12
Статус: утверждён пользователем; пересмотрен по итогам ревью (2026-11-13)

## Контекст и проблема

Сервер `doc_rag.server.mcp_http` грузил embedding-модель
(`BAAI/bge-m3`) лениво — при первом семантическом запросе
(`server/retrieval.py`, `raglib/vector_index.py`, `raglib/indexer.py`).
`SentenceTransformer(model_name)` без ограничений лезет в HF Hub; если
Hub недоступен или медленный, запрос поиска висит, и клиент получает 504.

## Решение (утверждено)

1. **Модель — часть поставки.** Snapshot модели скачивается один раз
   скриптом `scripts/fetch_model.py` в `models/bge-m3/` (каталог вне
   git), зашивается в docker-образ ранним слоем `COPY` и доставляется
   в прод деплой-механикой проекта. Рантайм-запросы на HF не ходят.
2. **Загрузка при старте.** Сервер грузит модель один раз в FastAPI
   lifespan-хуке, до приёма запросов, через единый общий загрузчик
   с `local_files_only=True`.
3. **Сверка с HF без подмены.** Сервер ходит на HF только для лёгкой
   проверки ревизии (метаданные, без скачивания): при старте и далее
   раз в N дней. Если веса изменились — **предупреждение в лог и UI
   с точной командой обновления** (`fetch_model.py` + restart +
   rebuild); никакой фоновой догрузки и подмены в рантайме.
4. **Параметр настройки.** `embeddings.update_check_interval_hours`
   в `config/config.yaml`, часы, по умолчанию 72. `0` — сверка
   выключена (air-gapped контур).
5. **Таймауты.** Метаданные — 10 с на вызов; скачивание — таймаут
   на чтение (`HF_HUB_DOWNLOAD_TIMEOUT`), общий бюджет не ограничен.
   HF недоступен → INFO/WARN в лог, работаем на локальной копии.
6. **Degraded-старт.** Модели нет → сервер стартует, семантический
   поиск возвращает явную ошибку с диагнозом, остальное работает.

По итогам ревью из дизайна исключена фоновая автоподмена модели
(«watcher с тихими окнами и атомарной подменой»): при весах, не менявшихся
с 2024 года, её сложность (VRAM-подмена, staleness, гонки с ingest)
не оправдана. Принята как осознанное техническое решение; при смене весов
оператор действует вручную по подсказке из UI/лога. Этим устранены
критичные замечания ревью C1 (три независимых кэша модели), C3 (скачивание
в живой каталог) и частично I1/I3/I9. Принятые компромиссы зафиксированы
в разделе «Не-цели».

## Спецификация

### Скачивание и хранение

- `scripts/fetch_model.py` — обёртка над `huggingface_hub.snapshot_download`
  с `ignore_patterns=["onnx/*", "imgs/*", "*.jpg", "*.webp", ".DS_Store",
  "README.md", "*.msgpack", "*.h5"]` (в репозитории модели 4.6 ГБ, из них
  серверу нужны ~2.3 ГБ: `pytorch_model.bin`, конфиги, tokenizer,
  `colbert_linear.pt`, `sparse_linear.pt`; safetensors в репозитории нет).
- Список хешируемых файлов весов: `pytorch_model*.bin`, `*.safetensors`,
  `*.pt` — фиксируется в `WEIGHTS.sha256` (формат `sha256sum`-совместимый:
  `<hash>  <path>`, отсортировано). Скачивание — в staging-каталог
  с последующей валидацией и атомарным `os.replace` в `models/bge-m3/`.
- `models/` в `.gitignore`. **Не добавлять** `models/` в `.dockerignore`.

### Docker

- Ранний слой `COPY models/ /app/models/` — условный, управляется
  build-arg `REQUIRE_MODEL` (`0`/`1`). CI (`.github/workflows/build.yml`)
  собирает с `REQUIRE_MODEL=0` — сборки PR без модели остаются зелёными.
  Релизная/деплойная сборка — `REQUIRE_MODEL=1`; при пустом
  `models/bge-m3/` сборка падает с внятной ошибкой (fail-fast).
- `ENV HF_HOME=/app/build/hf-cache` (записываемый каталог) — чтобы
  даже случайные служебные обращения hf_hub не писали в read-only слой.
- `COPY --exclude=models . /app` в финальном `COPY .` — проверено
  ревьюером на buildx 0.36.1 (Dockerfile syntax ≥ 1.19, `dockerfile:1`
  удовлетворяет); CI использует `setup-buildx-action@v3` — гарантия есть.
  Модель в образе ровно один раз.
- Учесть диск-бюджет buildx-кэша раннера (`mode=max` на 2.3 ГБ слоя).

### Загрузка при старте

- Lifespan-хук `mcp_http.py`: инициализация единого синглтона embedder-а.
  `SentenceTransformer(path, local_files_only=True)` — изоляция от сети
  на уровне загрузчика (глобальный `HF_HUB_OFFLINE=1` ставить нельзя —
  он сломает сверку).
- Единый загрузчик заменяет три места: `retrieval.py`, `vector_index.py`,
  `indexer.py`. Порядок поиска: `embeddings.model_path` (если задан) →
  `build/models/bge-m3` → `models/bge-m3`. Watcher при заданном
  `model_path` отключается.
- Thread-safe загрузчик с single-flight локом: холодный старт с 4 слотами
  `_TOOL_SEM` не должен поднять две копии модели в VRAM.
- Модели нет → degraded-старт: ERROR в лог с инструкцией (запустить
  `scripts/fetch_model.py` или пересобрать образ с `REQUIRE_MODEL=1`);
  сервер работает, семантический поиск — явная ошибка.

### Диагностика для оператора

- `indexed_catalog()` (`retrieval.py:270-283`) дополняется полями:
  `model_ready` (bool), `weights_sha256` (строка или null),
  `index_stale` (bool) + `stale_reason`.
- `semantic_search_ready` учитывает `model_ready`; `_FALLBACK_NOTICE`
  в `search_tool.py:77-81` разветвляется по причине (модель отсутствует /
  индекс не построен / индекс устарел) — оператор получает верный
  диагноз вместо «FAISS-индекс отсутствует, нажмите Rebuild».
- `_readiness_state()` (`mcp_http.py:1262-1302`): отсутствие модели
  или устаревший индекс попадают в `reasons`; `/health/ready` отвечает
  503, если семантический поиск неработоспособен.
- Баннер в UI (`Documents.svelte`, типы в `ui/src/lib/types.ts`):
  «веса модели обновились, требуется rebuild» при `index_stale`.
- Новые конфиг-ключи в `_FIELD_CONSTRAINTS` (`mcp_http.py`) и
  `ui/src/lib/configSchema.ts`.

### Сверка с HF (без подмены)

- Новый модуль `src/doc_rag/server/model_watcher.py`: только проверка.
- Триггеры: однократно при старте (после начала приёма запросов) и далее
  каждые `update_check_interval_hours`.
- Проверка: `HfApi.model_info(..., files_metadata=True, timeout=10)`;
  сверка хешей LFS-объектов файлов весов (`siblings[i].lfs.sha256`,
  проверено: вызов лёгкий, без скачивания) с `WEIGHTS.sha256` локальной
  копии. Изменения README/tokenizer-а обновлением не считаются.
- Веса изменились → WARN в лог + `index_stale`-подобный флаг
  `model_update_available` в `indexed_catalog()` → баннер UI с командой:
  `scripts/fetch_model.py && рестарт && doc-rag rebuild`.
- Ошибка сети → INFO в лог, повтор на следующем цикле. На поиск не влияет.
- Shutdown: отмена задачи в lifespan; недокачанных staging-каталогов
  при этой схеме нет (watcher ничего не качает).

### Защита от смешения ревизий (BUG-006)

- `IndexMeta` / `index_meta.json` дополняется полем `weights_sha256`
  (фингерпринт весов, которыми построен индекс).
- `_store_matches_config()` / `ensure_faiss_index`: несовпадение
  фингерпринта → **не** инкрементально дополнять смешанными векторами,
  а требовать полный rebuild (ясная ошибка/статус, не тихое смешение).
- При старте сервер сверяет фингерпринт загруженной модели с метой
  индекса; несовпадение → `index_stale=true`, `stale_reason`
  «weights fingerprint mismatch», баннер в UI.

### Развёртывание модели по каналам

- **Docker compose / DEPLOY.txt**: модель в образе (`REQUIRE_MODEL=1`).
- **rsync-деплой**: `models/` не входит в `git archive`/`git pull`;
  rsync-шаг должен переносить `models/` (и не сносить её `--delete`-ом —
  использовать `--exclude`/явный источник). Нативная установка
  (`bootstrap.sh` / `install_server_native.sh`): шаг вызывает
  `scripts/fetch_model.py`.
- **Deploy-архив**: `make_deploy_archive.sh` дополняется поверх
  `git archive` tar-потоком каталога `models/` из рабочего дерева
  (архив тяжелеет на ~2.2 ГБ gzip — осознанно).

## Не-цели

- Фоновая автоподмена модели и догрузка в рантайме (исключено по ревью;
  осознанный технический долг — см. историю ревью в git).
- Поддержка нескольких/альтернативных моделей, пиннинг ревизий в конфиге.
- Квантизация, GPU-специфика, fallback на другую модель.

## Ограничения

- Никаких обращений к HF из пути обслуживания запросов:
  `local_files_only=True` в загрузчике + `HF_HOME` на записываемом томе.
- Сетевые шаги watcher-а — с таймаутом; недоступность HF не блокирует
  ни старт, ни поиск.
- Смешение векторов разных ревизий в индексе исключено конструктивно
  (фингерпринт в мете), а не надеждой на аккуратность.
- Тексты файлов — ASCII и кириллица (правило репозитория).

## Осталось на усмотрение исполнителя

- Форма синглтона; тесты на `_load_embedder` патчатся отдельно
  (tests/test_vector_index.py ~16 мест, tests/test_dedup.py:548,
  raglib/migrate_vectors.py:84 — либо делегирующая обёртка, либо правка
  тестов входит в план).
- Какой helper резолвит `build/models/bge-m3` и `models/bge-m3`
  (`_root_dir()` vs `DOC_RAG_ROOT` — в проекте два корня, выбрать один
  и зафиксировать).
- Формулировки логов, точная структура `model_watcher.py`.
- Тесты: unit на сверку хешей; degraded-старт без модели;
  fingerprint-mismatch → отказ от инкремента; config-обвязка UI.
